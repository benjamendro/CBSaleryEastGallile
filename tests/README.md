# בדיקות אמינות — דשבורד שכר ותעסוקה, אשכול גליל מזרחי

השאלה שהחבילה הזו עונה עליה: **האם כל מספר שמוצג בדשבורד נגזר מהנתונים הגולמיים,
ומייצג אותם נאמנה?**

```bash
pip install -r tests/requirements.txt
sudo apt-get install -y libarchive-tools     # bsdtar — לחילוץ לוחות הביטוח הלאומי
python3 -m pytest                            # 199 בדיקות + שער כיסוי
npm install && npx vitest run                # 18 בדיקות על העמוד המרונדר
```

`p7zip 16.x אינו קורא RAR5` — הוא כותב קבצים ריקים בשקט. לכן החבילה מקבלת רק `bsdtar`,
ומדלגת עם הודעה מפורשת אם אינו מותקן, במקום לעבור על נתונים ריקים.

**אין mocks בשום מקום.** הבדיקות קוראות את קובצי המקור האמיתיים, מריצות את הצינור האמיתי
ומרנדרות את העמוד שפורסם. אין גבול חיצוני שדורש כפיל: העמוד מצייר SVG בעצמו ואינו טוען
ספרייה בזמן ריצה.

**`tests/_lib/sources.py` אינו מייבא דבר מהצינור.** הוא פותח את הגיליונות ב-openpyxl ומאתר
ערכים לפי המבנה שאדם רואה על המסך — שם גיליון, שורת כותרת, שם רשות, עמודת שנה. השוואה
שהייתה משתמשת בקוד הקריאה של הצינור הייתה מוכיחה רק שהצינור מסכים עם עצמו.

### מרקרים

**אף אחד מהם אינו סוטה מתא המקור.** כולל הכללים המחושבים: שחזור 2022 מרמת סדרי הענפים

מנפת צפת ונפת גולן, והשקלול לפי מספר עובדים.

### ✅ שרשרת המקור שלמה

`data.json` נבנה מחדש **זהה בית-לבית** משבעת קובצי הלמ"ס; `btl.json` — מ-180 לוחות הביטוח
הלאומי; `index.html` ו-`artifact.html` — מהתבנית ומשני קובצי הנתונים. **אין ולו מספר-נתון
אחד קשיח בתבנית**: אחרי הסרת CSS, קוד וקישור הגופנים נותרו בה רק שנים, וכל שנה שהיא מזכירה
מכוסה בנתונים. אף מספר בדשבורד אינו נכתב ביד.

### ✅ האינווריאנטים המתועדים מתקיימים

18 הרשויות = 83,774 שכירים = נפת צפת (57,776) + נפת גולן (25,998) · הממוצע האזורי הוא
הממוצע המשוקלל לפי מספר אנשים ולא ממוצע פשוט · הממוצע הארצי הוא 12,976 ₪, והסדרה
המבלבלת (13,514 ₪ למשרת שכיר) מופיעה בעמוד רק בתוך אזהרה שזו אינה היא ·
א׳ = ד׳ + ז׳ + ח׳ מתקיים **באפס סטייה** בכל רשות ובאשכול, בכל תשע השנים.

### ⚠️ שלושה ליקויים — מסומנים `xfail(strict=True)` ומוצמדים בבדיקה נוספת

הסימון `strict` אומר שברגע שליקוי יתוקן, הבדיקה תיכשל כ-XPASS ותדרוש להסיר את הסימון.
לצד כל אחד יש בדיקה שמצמידה את המצב הקיים, כדי שלא ישתנה בשקט.

1. **אותה רשות, שני שמות בעמוד אחד.** חלק א׳ וחלק ב׳ מאייתים ארבע רשויות אחרת:
   `קריית שמונה`/`קרית שמונה` · `טובא-זנגרייה`/`טובא-זנגריה` · `גולן`/`הגולן` ·
   `ג'ש (גוש חלב)`/`ג'ש )גוש חלב(`. **הנתונים משויכים נכון** — שתי הרשימות נפתרות לאותם
   18 קודים — אבל הקורא רואה שני שמות לאותה רשות.
2. **סוגריים הפוכים — והמקור הוא קובץ הצימודים.** `btl.json` נושא `ג'ש )גוש חלב(`, אבל
   הוא אינו ממציא אותו: זהו הערך שבעמודת „שם רשמי בלמס” ב-`eshkol_mapping.xlsx`.
   **לוחות הביטוח הלאומי עצמם כותבים `ג'ש (גוש חלב)` כשורה.** התיקון שייך לקובץ הצימודים.
3. **`fuzzy` עדיין נושא משקל בזמן ריצה.** שתי רשויות מתאימות רק דרך `difflib`.
   `CLAUDE.md` אישר ב-30/08/2026 להוסיף עמודת „שם בביטוח לאומי” ל-`eshkol_mapping.xlsx`
   ולא להסתמך על fuzzy — העמודה טרם נוספה.

### 📌 פגם במקור שהוצמד

**לוח 45 של הביטוח הלאומי כותב `מבואות\nהחרמון` — עם ירידת שורה בתוך השם.** בכל שאר
הלוחות השם תקין. קורא שמשווה שמות מילולית מאבד את המועצה הזו מהתפלגות השכר בלבד — פער
שקשה להבחין בו. הצינור מנרמל רווחים ולכן חסין; יש בדיקה שמצמידה את ההתנהגות הזו.
אותו פגם מופיע גם ב-`unified_galil_mizrahi.csv` שסופק עם הנתונים.

## הדוחות האיכותניים

`analysis/dashboard-insights.md` (14 תובנות) ו-`analysis/report.html`. **כל מספר בכל 14
התובנות אומת מול הטבלה שהיא מצטטת** — כולל ערכי p, מקדמי מתאם ומבחני שונות. `report.html`
נבנה מחדש **בית-לבית** מ-`report_data.json`, ותוכנו הוצלב מול הפלטים שהצינור מייצר.

`dist_vs_peers.csv` — כל בסיס הראיות של תובנה 2 — **שוחזר ידנית מהמאסטר, שורה בשורה,
עד הספרה האחרונה**, למרות שאין לו קוד במאגר.

### ⚠️ ארבעה ממצאים

1. **שגיאה בתובנה 6ג.** „גליל עליון היא היחידה באשכול שמנצחת את הארצי בשני הקצוות” —
   במדד „לחודש עבודה”, שממנו מגיעים ה-29.9% וה-11.4% שהתובנה עצמה מצטטת, **גם גולן
   מנצחת בשני הקצוות** (28.4% מול 29.9%, ו-11.5% מול 11.4%). הטענה שורדת רק משום
   שהיא משווה ערכי רשות **מעורבבים** לערך ארצי **חד-מדדי**.
2. **`authority_profile.csv` מערבב שני מדדים.** עמודות ההכנסה בו נלקחות ב-`aggfunc='mean'`
   על **שני** לוחות קבוצות ההכנסה — „ממוצע לחודש בשנה” (ארצי 35.5%) ו„ממוצע לחודש עבודה”
   (ארצי 29.9%) — בעוד `income_dist.csv` מסנן לשני בלבד. לכן אותו גודל מקבל 38.3% בקובץ
   אחד ו-35.0% באחר. במבחן „רשויות ההשוואה” (תובנה 2) שני הצדדים מעורבבים, ולכן הממצא שם
   אינו נפגע.
3. **ארבעה קובצי פלט אין להם מייצר במאגר:** `dist_vs_peers.csv`, `self_vs_employee.csv`,
   `anaf_authority_ratio.csv` ו-`report_data.json`. המספרים תקינים, אבל **שינוי בנתונים
   לא יגיע אליהם**.
4. **`analysis/output/` ישן מהקוד.** הרצה מחדש משנה את שמות רצועות ההכנסה —
   `report_data.json` כבר נושא את החדשים, `income_dist.csv` עדיין את הישנים.

### הערות מדויקות יותר

- **תובנה 13** מצדיקה את עמודת 2022 בעוגן **83,774** — נתון **2024**. בקובץ 2022 סכום
  18 הרשויות הוא 84,536 מול עמודה של 83,816: קרוב, אך לא „במדויק” כפי שנכתב. המסקנה עצמה
  עומדת.
- **תובנה 11** מציגה טבלה של 366 מתוך 369 התאים — יסוד המעלה (3 תאים) הושמטה בלי ציון.
- **תובנה 5**: גבולות אפקט ההרכב (‎+1.3 עד ‎+2.8) אינם ניתנים לשחזור מהתיאור, כי הרצועה
  העליונה פתוחה והמסמך אינו אומר באיזה חסם השתמש.
- עיגולים: קריית שמונה 1,924 ולא 1,923 (תובנה 4) · סך הפער 2,685 ולא 2,684 (תובנה 13).

## שער הכיסוי

`pytest.ini` מגדיר `--cov-fail-under=80` על `eshkol-matching/` ועל `tests/_lib/`.
**אומת שהשער באמת נורה:** ב-`--cov-fail-under=99` הריצה יוצאת בקוד 1, ובסף המוגדר בקוד 0.

ב-Vitest **אין** שער כיסוי, בכוונה: קוד הדשבורד נשלח משובץ בתוך HTML מיוצר, ולכן v8 אינו
יכול לייחס אותו לקובץ מקור — סף כזה היה קישוט. הכיסוי הנמדד יושב בצד הפייתון, על מודולים
אמיתיים.
